# 03 · Архитектура

## Стек и почему

| Слой | Выбор | Почему |
|---|---|---|
| Язык | Swift 6 (strict concurrency), iOS 18+ | Как в Nomaded. API новее — под `if #available` |
| UI | SwiftUI | Меню, HUD, «Ереже», коллекция |
| Рендер | **Metal** (ADR-001) | 120 fps на ProMotion. Берём устройство из `GlobeMetalView` Nomaded |
| Физика | **Jolt Physics 5.6** через C-фасад (ADR-002) | Детерминизм, непрерывные столкновения (CCD) для мелких быстрых костей, сохранение и восстановление состояния мира для бота |
| Хаптика | Core Haptics | Непрерывное натяжение и паттерны по импульсу удара |
| Звук | AVAudioEngine | Пул голосов, высота по массе и импульсу |
| Данные | SwiftData, локально (ADR-008) | Профиль, статистика, «Жол», «Қалта» |
| Тесты | Swift Testing | Правила, классификатор, детерминизм, частоты сторон |

## Слои и поток данных

```
 Палец ──► Input ──► ThrowInput(angle, power, spin)
                          │
                          ▼
   ┌────────────── Simulation (Jolt, фикс. шаг 240 Гц) ──────────────┐
   │  тела, контакты, сон                                            │
   └──────┬───────────────────────┬──────────────────────┬───────────┘
          │ позы для кадра        │ события контактов    │ всё уснуло
          ▼                       ▼                      ▼
     Render (Metal)        Feel (хаптика, звук)    Judge: геометрия → ThrowOutcome
                                                         │
                                                         ▼
                                              Rules (чистый Swift)
                                     MatchState + ThrowOutcome → MatchState'
                                                 + RefereeCall
                                                         │
                                                         ▼
                                     Features (SwiftUI): HUD, судья, следующий ход
                                     Bot: планирует следующий ThrowInput
```

**Главная идея.** Правила ничего не знают о физике, а физика — о правилах. Между ними `Judge`: когда всё остановилось, он превращает позы тел в факты («кеней №4 за кругом», «кеней №7 между параллельными линиями», «сақа легла тәйке»). `Rules` — чистая функция над фактами, её покрываем тестами на каждый пункт Регламента.

## Физика

### Jolt через C-фасад (ADR-002)
- **`Packages/AsyqPhysics`** — локальный Swift-пакет из двух таргетов:
  - `CJolt` (C++): исходники Jolt нужной версии, вендорим в репозиторий, плюс наш маленький C-фасад `asyq_physics.h`. В нём только то, что нужно игре: мир, выпуклые тела, шаг, контакты, сохранение и восстановление состояния.
  - `AsyqPhysics` (Swift): удобная типобезопасная обёртка над фасадом.
- **Почему свой фасад, а не C++ interop в приложении.** Таргет приложения остаётся чистым Swift, без `-cxx-interoperability-mode`. Компиляция быстрее, ошибки понятнее. Готовая обёртка [joltc](https://github.com/amerkoleci/joltc) (MIT) — запасной вариант, если свой фасад разрастётся. Решаем в M1.
- **Флаг `JPH_CROSS_PLATFORM_DETERMINISTIC`.** Одинаковый результат на всех устройствах и версиях компилятора, ценой нескольких процентов скорости. Нужен будущему онлайну.

### Мир
- **Масштаб.** Асык ~3 см, поле 12 м. Если на реальном масштабе тела дрожат, масштабируем мир (×10) и пересчитываем гравитацию. Проверяем в M1.
- **Шаг** 240 Гц фиксированный, рендер интерполирует между шагами. Сақа с CCD (`LinearCast`).
- **Сон.** Тело засыпает ниже порога скорости. Через 4 с после броска всё засыпает принудительно, чтобы ход не висел.
- **Массы** из Регламента: кеней 15–17 г, сақа 28–30 г. Трение и упругость по парам материалов — в `GameTuning` (стартовые значения в [research/game-design.md](research/game-design.md#материалы-и-масштаб)).

### Форма кости и стороны
- **Модели — сканы настоящих асыков** (ADR-003): Object Capture → USDZ → `Tools/AsykPipeline` → `.asyk`. В файле: меш для рендера (2 LOD), выпуклая оболочка для физики, масса и центр масс, «нижние» нормали шести сторон (алшы, тәйке, бүк, шік, омпы, шоңқай).
- **Пока сканов нет** — `PlaceholderAsyk`: процедурная форма в коде с теми же шестью сторонами.
- **Выпуклой оболочки достаточно.** На ровном полу кость опирается именно на неё, вогнутости на позу почти не влияют.
- **`PoseClassifier`.** Когда тело уснуло, берём направление гравитации в системе координат кости и выбираем сторону с самым близким направлением (максимальное скалярное произведение).
- **Калибровка частот.** Цель: бүк и шік ~40% каждая, алшы и тәйке ~10%, омпы и шоңқай доли процента. Уточняем по 200 настоящим иіру Leon. Если частоты не сходятся, правим массу, центр масс и трение, но не рандом.

### Детерминизм и реплеи
- Ход — это `ThrowInput(angle, power, spin)` плюс начальное состояние стола. Одинаковый ввод → одинаковый результат.
- **Что это даёт уже в v1.0:** бот просчитывает броски на копии мира, сцены в «Ереже» хранятся тремя числами, реплей лучшего удара бесплатен.
- **Что это даёт в v1.2 (онлайн):** ход по сети — несколько байт, реплей у соперника проигрывается локально. В матче хранится версия физики. Если версии расходятся, показываем только счёт.
- **Тест:** один и тот же ввод N раз → побитово одинаковое конечное состояние.

### Slow-mo
`TimeScale` замедляет только темп, с которым мы продвигаем симуляцию относительно реального времени. Шаг физики всегда 1/240 с, поэтому замедление не меняет результат.

## Рендер

- `ArenaMetalView`: `CAMetalLayer` + `CADisplayLink` до 120 Гц, рисуем по требованию (когда всё спит и камера стоит, кадры не рисуем). Порт `GlobeMetalView` из Nomaded.
- Проходы: тени (shadow map для ключевого света + контактные тени), поле, кости (инстансинг: 15–20 одинаковых мешей), разметка, глубина резкости в slow-mo.
- `BoneMaterial`: «обёрнутое» освещение для подповерхностного света, AO и normal map из скана, вариант с глянцевой краской.
- `ArenaCamera` на `SpringValue`: за спиной, полёт за сақой, облёт удара, вид сверху.

## Бот

- **`BotPlanner`** работает в фоне на своей копии мира. Сохраняем состояние Jolt, пробуем 20–60 кандидатов `ThrowInput`, оцениваем результат («сколько выбито», «где легла сақа», в Шыре — «насколько я уязвим») и выбираем лучший.
- **Уровень** — это человеческий разброс по углу и силе, который добавляется к лучшему броску, плюс глубина перебора.
- **Персонаж** (`BotPersona`) — веса в оценке: осторожный, батыр, хитрец.

## Конкурентность (Swift 6)

- UI, рендер и основной `PhysicsWorld` — на `@MainActor`, шаги симуляции в колбэке дисплей-линка (20 тел при 240 Гц — дёшево).
- Бот — отдельный `actor` со своим экземпляром `PhysicsWorld`. Между ними ходят только `Sendable`-значения: снимок состояния и `ThrowInput`.
- `Rules` и `Judge` — чистые `Sendable`-типы без состояния.

## Данные

SwiftData, только локально (ADR-008): `Profile` (имя, язык, левша), `MatchRecord`, `Stats`, `Unlock` (сақи, краски, этапы «Жол»). Синхронизацию через iCloud можно добавить позже, если поля проектировать по правилам CloudKit сразу: только добавляем, у всех значения по умолчанию.

## Локализация

String Catalog, языки `kk`, `ru`, `en`. Казахские тексты вычитывает носитель-редактор (платно, обязательно). Игровые термины в ключах не переводятся, а описываются в словаре.

## Тесты

| Что | Как |
|---|---|
| Правила «Бес табан» | Сценарий на каждый пункт Регламента: серия с края круга, «Параллель», «Диагональ», «Бес табан», партия, матч, фолы |
| Правила Шыра | Жаттым, Өлді, пары, алшы → ещё бросок, тәйке → перенос, конец кона и матча |
| `Judge` | Геометрия: выбит/не выбит на границе, полосы параллельных линий |
| `PoseClassifier` | Все шесть положений + наклонённые позы |
| Частоты сторон | Headless: 10 000 иіру попадают в коридор |
| Детерминизм | Один ввод → одинаковое состояние |
| Бот | Средняя результативность уровня в коридоре |

## DEBUG launch-аргументы

Проверка без касаний, как в Nomaded. Первые: `-AsyqDebugScene bestaban|shyr|iiru`, `-AsyqDebugThrow angle,power[,spin]`, `-AsyqGallery YES`. Полный список ведём в `CLAUDE.md`.

## Журнал решений (ADR)

### ADR-001 · Рендер на Metal (2026-11-13, принято)
**Контекст.** Нужны 120 fps и полный контроль над светом и материалом кости. В Nomaded RealityKit на iPhone упёрся в 60 fps, и глобус перевели на Metal (там ADR-010). SceneKit Apple объявила устаревшим.
**Решение.** Свой рендер на Metal, устройство берём из `GlobeMetalView`.
**Цена.** Больше кода, чем в RealityKit: тени, материалы и камеру пишем сами.

### ADR-002 · Физика на Jolt (2026-11-13, принято Leon)
**Контекст.** Мелкие быстрые тела, нужен детерминизм (бот, сцены «Ереже», будущий онлайн) и сохранение состояния мира.
**Решение.** Jolt Physics 5.6.0 (MIT), исходники вендорим в `Packages/AsyqPhysics` с фиксированной версией. Доступ через свой C-фасад. Флаг `JPH_CROSS_PLATFORM_DETERMINISTIC`.
**Цена.** Сторонняя зависимость на C++. Обновляем только осознанно, с прогоном теста детерминизма. Лицензию MIT указываем в «Ереже» → «О приложении».

### ADR-003 · Модели костей — сканы настоящих асыков (2026-11-13, принято Leon)
**Решение.** Leon покупает асыки и сақи и сканирует их через Object Capture (на iPhone или по фото на Mac через `PhotogrammetrySession`). До сканов работаем на процедурной форме `PlaceholderAsyk`.
**Риск.** Предмет в 3 см может плохо сканироваться. Запасной план — макросъёмка с большим числом кадров, затем Blender по фото.

### ADR-004 · Арт-дирекшн «Минимализм + живые кости» (2026-11-13, принято Leon)
Чистая тёплая сцена, реалистичные кости-герои, орнамент тонким акцентом. Подробно — в [02-design.md](02-design.md).

### ADR-005 · Скоуп v1.0 (2026-11-13, принято Leon)
«Бес табан» и Шыр против ботов, иіру, обучение, «Ереже», лёгкие «Жол» и «Қалта». Онлайна и игры на одном телефоне в v1.0 нет, но архитектура готова к онлайну (ход = `ThrowInput`, детерминизм).

### ADR-006 · Правила: «Федерация» строго по Регламенту (2026-11-13, принято)
Режим «Бес табан» следует Регламенту 2011–2022. Каждое отступление и каждое толкование спорного места записываем в [05-rules.md](05-rules.md) с номером страницы. Исключение для игры с ботом — нет таймера партии.

### ADR-007 · Только iPhone, портрет, iOS 18+ (2026-11-13, принято)
Игра одной рукой, как в жизни бросают одной рукой. iPad — после v1.0, если будет спрос.

### ADR-008 · Данные локально, без iCloud в v1.0 (2026-11-13, предложено)
Меньше движущихся частей к релизу. Модели проектируем совместимыми с CloudKit, чтобы включить синхронизацию позже без миграций.
